CHAPTER 01

环境规划与备份

先分离系统、工具与项目数据。

目录与版本

本次实测：Python 3.13.17、Node.js 24.22.3、Git 2.56.1.windows.1、VS Code 1.147.0、PHP 8.5.13、Apache 2.4.71、MariaDB 10.11.19、phpMyAdmin 5.2.3。版本仅为 2026-11-24 实测记录，并非最新版本推荐。项目保存在 E:\projects，XAMPP 位于 E:\xampp；其他机器按实际路径调整。

恢复顺序

备份项目和数据库 → 安装运行环境 → Git 认证 → 编辑器配置 → XAMPP → 项目验收。优先官方安装包；不必为统一目录移动已有项目。

重装前先备份

保留项目及隐藏 .git、配置、网站文件和数据库 SQL。检查独立备份介质，切勿误格式化数据盘。

CHAPTER 02

Python 环境

独立虚拟环境，按项目管理依赖。

安装

从 https://www.python.org/downloads/windows/ 获取受支持版本的 Windows x64 安装程序，传统安装器勾选 Add python.exe to PATH。重新打开 CMD。

python --version
py --version
where python
python -m pip --version
python -m pip install --upgrade pip

项目测试（CMD）

在一个新的空测试目录中执行；虚拟环境内 pip 与全局 pip 独立。

mkdir D:\dev-test\python-test
cd /d D:\dev-test\python-test
python -m venv .venv
.venv\Scripts\activate
python -m pip install requests
python -c "import requests; print(requests.__version__)"
deactivate

依赖恢复

已有项目按其依赖清单安装，不提交 .venv 或 __pycache__。

python -m pip install -r requirements.txt

路径与依赖恢复

WindowsApps 可能只是执行别名；使用 sys.executable 核对实际解释器。已有项目保留依赖清单，重新创建 .venv，不复制旧虚拟环境。

CHAPTER 03

Node.js 环境

优先 LTS，使用项目级 npm 依赖。

安装

从 https://nodejs.org/en/download/ 下载 Windows x64 LTS MSI，保留 npm 和 PATH 组件；原生编译工具按需安装。

node -v
npm -v
npx -v
where node

项目测试（CMD）

在新的空目录执行；成功输出时间并生成 package.json、package-lock.json 和 node_modules。

mkdir D:\dev-test\node-test
cd /d D:\dev-test\node-test
npm init -y
npm install dayjs
node -e "console.log(require('dayjs')().format('YYYY-MM-DD HH:mm:ss'))"

恢复依赖

已有 lockfile 的项目使用 npm ci；不要提交 node_modules。

npm ci

项目文件

package.json 声明依赖，package-lock.json 锁定解析版本，node_modules 可重建。npm ci 要求锁文件一致并清理现有依赖目录。

CHAPTER 04

Git 与 GitHub

恢复身份、凭据及已有仓库，不重复初始化。

安装

https://git-scm.com/download/win 下载 x64 Setup，选择 Git from the command line and also from 3rd-party software，保留 Git Credential Manager。

git --version
where git

全局配置（CMD）

用户名和邮箱替换为自己的 GitHub 提交信息；公开仓库建议使用 GitHub noreply 邮箱。逐行执行。

git config --global user.name "YOUR_NAME"
git config --global user.email "YOUR_VERIFIED_EMAIL"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"
git config --global core.longpaths true
git config --global --list

身份认证

使用浏览器授权，不需要把 Token 写入配置。

git config --get credential.helper
git credential-manager --version
git credential-manager github login
git credential-manager github list

已有仓库验收

进入已有仓库根目录；先检查再同步。模拟推送不修改远程，不能完全证明实际写入成功。

git status
git remote -v
git fetch origin
git branch -vv
git push --dry-run origin main

身份、认证和远程是三件事

user.name / user.email 是提交身份；Credential Manager 是 HTTPS 访问认证；remote 指向远程仓库。已有 .git 不重复初始化，main 按实际分支调整。

CHAPTER 05

VS Code 配置

统一编辑器，精简扩展，保护历史代码。

安装

https://code.visualstudio.com/download 下载 Windows x64 Stable，勾选 Add to PATH 和文件夹右键菜单。普通用户运行。

code --version
where code
code --list-extensions

扩展管理

使用 configs/vscode/extensions.txt 的 13 项清单。Ctrl+Shift+X 搜索 ID 安装；网络不稳定时逐个安装。设置同步可能恢复旧扩展，清理前暂停同步。

code --install-extension ms-ceintl.vscode-language-pack-zh-hans
code --list-extensions

配置替换

关闭 VS Code，备份 %APPDATA%\Code\User\settings.json，再复制模板到该目录。模板 PHP 路径按机器修改。保留手动格式化与工作区信任；项目级配置优先。

备份扩展（CMD）

将清单保存至当前目录。

code --list-extensions > vscode-extensions.txt

中文化与配置入口

Ctrl+Shift+X 安装中文语言包；Ctrl+Shift+P 搜索 Configure Display Language 选择简体中文并重启。通过 Open User Settings (JSON) 打开用户配置。本次同步恢复历史扩展后由 26 项精简至 13 项，按需安装，不强制所有机器一致。

文件 → 打开文件夹；终端 → 新建终端。PHP 使用 XAMPP，不使用 Live Server 解析。

CHAPTER 06

PowerShell 集成

处理 npm.ps1 与虚拟环境脚本限制。

执行策略

如果 npm 在 CMD 正常、PowerShell 报 PSSecurityException，先检查策略。个人开发机可选择 CurrentUser RemoteSigned；组织策略不可绕过。不想改变策略时使用 npm.cmd。

Get-ExecutionPolicy -List
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
npm --version
npx --version

集成终端

在 VS Code 终端执行。

python -c "print('Python environment OK')"
node -e "console.log('Node.js environment OK')"
git --version

虚拟环境（PowerShell）

进入已有测试目录，若已删除则重新建立空目录。

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -c "import sys; print(sys.executable)"
deactivate

区分终端

CMD：where python、cd /d E:\projects；PowerShell：where.exe python、cd E:\projects。修改 PATH 后关闭并重开终端与 VS Code。下载脚本只在确认来源可信后解除单文件锁定。

CHAPTER 07

XAMPP / PHP / MariaDB

从服务到 CLI，再到实际项目。

迁移与服务

本次从其他电脑复制 E:\xampp，先备份 htdocs 和数据库（优先逻辑导出，物理复制须停库且版本兼容）。启动 Apache、MySQL；访问 http://localhost/dashboard/ 和 http://localhost/phpmyadmin/。路径不同才考虑备份后运行 setup_xampp.bat。

& "E:\xampp\apache\bin\httpd.exe" -t
& "E:\xampp\php\php.exe" -v
& "E:\xampp\php\php.exe" --ini
& "E:\xampp\php\php.exe" -m

PATH 配置

Win+R 输入 sysdm.cpl → 高级 → 环境变量 → 用户 Path，新增 E:\xampp\php 和 E:\xampp\mysql\bin。重启终端与 VS Code。

php -v
where.exe php
php --ini
mysql --version
mysqldump --version

扩展及参数

备份 php.ini 后按 configs/php/development.ini.example 修改已有项，不覆盖整个文件。启用 gd、intl、sqlite3、zip；重启 Apache。CLI 的执行时间可能与 Web 不同，使用本地 PHPInfo 核对 Web 值。

php -m
php -i | Select-String '^(memory_limit|upload_max_filesize|post_max_size|max_execution_time|max_input_time|max_input_vars|date.timezone|display_errors|log_errors|error_reporting|extension_dir) =>'

PHP 实测

在 E:\xampp\htdocs\php-test 创建 test.php，写入以下代码并保存。

<?php
echo "PHP environment OK";

终端与浏览器

用 VS Code 打开 php-test 文件夹，新建终端执行；浏览器访问 http://localhost/php-test/test.php，应显示 PHP environment OK。故意删除分号并保存，检查问题面板，再恢复。测试完删除临时目录。

php -l test.php
php test.php

兼容性与安全

PHP 8.5 本地运行不代表旧生产版本兼容。按项目设置最低 PHP 版本，恢复 WordPress 后检查后台、图片上传、插件和数据库。XAMPP 仅供本地开发，不对公网开放；PHPInfo 不公开。

本地配置目标及数据恢复

memory_limit 512M、upload_max_filesize 256M、post_max_size 300M、max_input_vars 5000、时区 Asia/Shanghai；Web 执行时间按需设置 300。四个新增扩展 CLI 已验证；Web 参数逐项核验仍待确认。

数据库优先 SQL 逻辑备份与独立测试库导入，不能盲目覆盖 mysql/data。WordPress 文件和数据库成套恢复，检查生产 PHP 兼容性。

CHAPTER 09

故障排查

记录真实问题，优先最小改动。

命令无法识别

检查 PATH 和实际安装位置，重新启动终端。两条 Git 命令粘贴成一行会报 no action specified，逐条执行。

where.exe git
where.exe code

VS Code 权限冲突

Another instance of Code is already running as administrator：保存文件，关闭所有 VS Code 窗口，必要时结束残留进程，以普通用户重新打开。

扩展下载失败

socket hang up / ECONNRESET：取消批量任务，检查网络与代理，通过图形界面逐个安装；不要关闭 TLS 校验。

code --list-extensions

认证取消

User canceled device code authentication：先检查账号列表，再按需重新登录。

git credential-manager github list

临时配置反复出现

设置同步或 Postman 可能重新写入旧配置和临时指令路径。备份后清理，不删除云端数据；检查扩展是否重新生成。

路径不存在

测试目录已删除不代表运行环境故障。重新创建空测试目录即可。

Codex 暂缓

本次安装未成功，未纳入基础验收；不影响其他工具，后续单独研究。

CHAPTER 11

环境自动检测

只读探测，生成 JSON / Markdown 报告。

快速开始（PowerShell）

在仓库根目录执行。XAMPP 路径按实际调整；默认不检查本地服务端口。

.\scripts\check-environment.ps1 -XamppRoot "E:\xampp" -CheckLocalServices -ReportDirectory "$env:TEMP\dev-environment-reports"

如果下载的脚本被 RemoteSigned 阻止，先审阅源码，确认可信后仅对该脚本解除锁定；不要绕过组织策略。

Unblock-File -LiteralPath ".\scripts\check-environment.ps1"

查看报告

实机记录：50 PASS、0 WARN、0 FAIL、3 SKIP。此结果不是所有机器的保证；端口检测仅代表 TCP 连接成功。

打开可视化检测报告 ↗脱敏示例 JSON ↗检测工具说明 ↗下载检测脚本 ↗

检测边界

下载完整仓库；扩展检测依赖配置清单。npm.cmd 通过不等于 npm.ps1 可执行；PATH 中 PHP 不一定来自指定 XAMPP。WARN 即使退出码为 0 也需复核；SKIP 不是通过。
